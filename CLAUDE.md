# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

BossHide is a simple platformer. The player must reach the end of the level without being spotted, while doing tasks and actions along the way. In the story, an employee is trying to reach the toilets without being seen by the boss.

The project uses Godot 4.3 with the GL Compatibility renderer. `Game.tscn` (`game/game.gd`) is the main scene. It opens on a main menu drawn as an employee ID badge hanging from a lanyard on an office wall (`MenuPrincipal/Decor`: a clock showing the PC time, `ui/office_clock.gd`; an "Employee of the Month" frame with the boss, "The Boss (again)"; a dark "TEAMWORK" poster; a "TOILETS ->" sign taped "OUT OF ORDER DURING WORK HOURS"; skirting board and carpet), the badge and swinging slowly (`UiFx.swing` around the top of the cord, `Game.BADGE_PIVOT`): company header with a status light, an ID photo (`ui/id_photo.gd`), the "BossHide" title, employee details and a barcode (`ui/barcode.gd`), then the slogan and a row of buttons drawn as objects fixed to the wall (`ui/wall_device_button.gd`, `WallDeviceButton`, with the `TimeClockButton`, `ClipboardButton`, `ShredderButton` and `AlarmButton` theme variations; the script only draws the details above the text, since a script `_draw` paints over the button text): a time clock "Clock in" which starts level 1, a clipboard "Pick a mission" for the level select, a shredder "Shred my file" that erases the progress, and a red "BREAK GLASS" box "Resign" to quit, hidden in the Web build since a browser tab can't be closed (`Game.can_quit`). The shredder opens a confirmation over the menu (`ConfirmationBroyage`, "Shred your employee file?", the menu buttons disabled like with the photo picker): "Keep it" (focused) or Esc cancels, "Shred it" deletes the save file and resets the unlocked levels, best scores and badge photo. "Clock in" turns the light green, stamps a green "ACCESS GRANTED" on the badge and disables the buttons, then starts level 1 after `clock_in_delay` seconds (0.5 by default; the game tests set it to 0); going back to the menu resets the badge. Clicking the badge photo (a flat `BoutonPhoto` over it, also reachable with Up from the menu buttons) opens "Pick your ID photo", a grid of 10 icons drawn by `IdPhoto` (six employee types and four office objects, listed in `game/employee_profile.gd`); picking one changes the badge photo, Esc or "Keep this one" cancels, and the menu buttons are disabled while it is open. The choice is saved (`EmployeeProfile`), and the game passes it to each level with `set_employee_icon()`, which staples it as an ID photo on the HR warning. The level select screen ("Today's missions") has one button per level plus "Back to lobby" (Esc also goes back); a locked level reads "(locked by HR)"; only unlocked levels are playable, level 1 at first, and succeeding at level N unlocks N+1. A level already succeeded shows its best score under its name ("Best: 780"); replaying worse keeps the best, while the end screen total still adds up the latest score of each level. The unlocked levels, the best score of each level and the badge icon are saved in `user://save.cfg` (`game/save_data.gd`, `SaveData`, a `ConfigFile`; the scores of the current run and the annual review total are not): the game loads it in `_ready` and saves after each success and each photo choice. A missing or unreadable file gives the defaults, and wrong values are ignored one by one (`LevelSequence.restore`, `EmployeeProfile.select`); a level with a best score unlocks the next one. Menus work with the arrow keys and Enter or the mouse. Esc during a level pauses it: the level stays loaded but is disabled (`PROCESS_MODE_DISABLED`, so the player, managers and timer freeze) and a "Coffee break" menu offers "Back to work" (or Esc again), "Change mission" (level select) and "Go home early" (main menu), the last two abandoning the level. When a level ends, an end screen appears over the frozen level behind a dark veil. On success a toilet paper dispenser at the top of the screen (`ui/toilet_paper.gd`, `ToiletPaper`) carries a green "VACANT" sign and unrolls a perforated strip with a torn end, split into four sheets (`SHEET_HEIGHT`); each line is printed on it and appears when the paper reaches it (`unroll`, 0.8 s), then a green "NO EVIDENCE" stamp (`LevelResult.APPROVAL_STAMP`) falls on the third sheet and a grey boss's note fills the last one. The texts play a boss who suspects everything but can't prove anything: the line under "Level n complete!" and the boss's note are each drawn at random once per level from `LevelResult.SUSPICIONS` and `LevelResult.BOSS_NOTES`. The receipt also shows the time, the score, a rank from the score (`LevelResult.rank`: Toilet Ninja from 900, Professional Slacker from 700, Coffee Break Specialist from 500, Overworked Intern from 250, otherwise Employee of the Month) and the best score ("Best: 780", prefixed with "New best!" on the first success or when the record is beaten), with the buttons "Next mission" ("Clock out" on the last level), to the right of the paper, "Redo it (unpaid)" and "Mission list". On game over the screen is a written warning from HR (`level/hr_warning.gd`, `HrWarning`): which manager spotted the player (watching or patrolling, remembered by a second `body_spotted` connection bound to the manager), reasons ticked from the player's state (always "Not at desk", "In possession of a stolen key" if carrying the key, "Knows confidential codes" once the post-it was read), a sanction fixed per level, and the time with the wrong codes and wrong answers counted by `LevelScore`. A surveillance camera shot is stapled to it: the last frame drawn, cropped around the player (`ui/surveillance_shot.gd`), with a red frame on them and a green CCTV look (`ui/cctv.gdshader`); headless runs have no frame, so it shows "NO SIGNAL". A red "BUSTED!" stamp falls on the sheet, with the buttons "Try again" and "Mission list". Once the level is over, another detection changes nothing. The first button has the focus. The game passes the level number and whether it is the last level with `configure()`, and the best score with `show_best()`; the texts come from `level/level_result.gd`. Esc on a level's end screen, or on the end screen of the game, returns to the level select screen. Esc closes the keypad panel and is ignored during the colleague's question. The level marks Esc as handled so the game doesn't process the same press again. The game loads the levels listed in `Game.LEVELS` one at a time as a child named `Niveau`, shows "Level n/N" at the top, and keeps each level's score (`game/level_sequence.gd`, replaying a level replaces its score). After a success, Enter (the focused Next button, or the `next_level` action) loads the next level and R replays the same one; after a game over, R replays it. After the last level, an end screen shows the total score as an "Annual review" and R starts again from level 1.

The whole interface uses one theme, `ui/theme.tres`, set as `gui/theme/custom` in `project.godot`: sarcastic office look with yellow post-it buttons (red marker outline on focus), memo-paper panels, Patrick Hand as the default font and Permanent Marker for titles (`assets/fonts/`, with their licenses). Labels shown over the level use the `HudLabel` variation (white with an outline); `TitleLabel`, `StampLabel` and `VacantLabel` are the other variations. `ui/ui_fx.gd` (`UiFx`) holds the Tween animations (`pop_in`, `stamp`, `shake`, `wobble`); don't use them on a Container's child, which resets scale and rotation. In the menu, the badge photo and the three wall objects are `GlowButton`s (`ui/glow_button.gd`): a yellow halo pulses softly at rest and lights up on hover, with a hand cursor; the time clock light blinks and "Click to change ^" sits under the photo, while the decorative wall objects stay still. In a level, `level/interaction_hint.gd` (`InteractionHint`) decides what E does from what is in reach (keypad, post-it, door, key, desk, in that priority) and `_press_work` uses it; levels show no interaction hint. The level select screen is a cork board (`ui/cork_board.gd`, `CorkBoard`) where each level is a ruled yellow post-it (`StickyButton` variation, drawn by the scripted StyleBox `ui/ruled_sticky_style.gd`, `RuledStickyStyle`) pinned by its top-left corner (`ui/push_pin.gd`, `PushPin`) and tilted by a fixed angle (`Game.TILTS`); the grid resets rotation when it sorts, so the game re-applies the tilts on its `sort_children` signal. A locked level is a faded post-it with a small red "LOCKED" stamp. The game over warning is a beige memo signed "- The Boss". Interface tests that check the layout put the scene in a `SubViewport` at the game size, because the headless window is tiny.

Each level is its own scene in `levels/` using `level/level.gd`, which emits `succeeded(score)`, `restart_requested`, `next_requested`, `menu_requested` and `pause_requested` for the game. A level must contain `Player`, `Arrivee` (goal) and `Interface` (an instance of `level/hud.tscn`, which holds the messages, timer and panels). In `_ready`, `level.gd` adds an open-space backdrop behind every level that has no `Decor` node (`level/office_backdrop.tscn`: a `ParallaxBackground` whose layer scrolls at half speed and repeats a 1200 px tile drawn by `level/office_backdrop.gd`, `OfficeBackdrop`: a tiled false ceiling down to y = -480 (`CEILING_Y`), wall, ceiling neons, windows with sky and buildings, "SYNERGY" and falling "Q4 GOALS" posters, a clock, low partitions, a plant, skirting and carpet, in dark muted colors so the gameplay rectangles stand out). It also adds the player's own desk under their starting point when the level has no `BureauPerso` (`level/home_desk.tscn`, a real desk in the `desks` group, drawn by `ui/home_desk_visual.gd` with a screen, a TODO pile, a mug, a "YOU" plate and the badge photo, which `set_employee_icon()` updates), placed just before `Player` so the player is drawn in front. Desks and managers are found by group (`desks`, `managers`, `patrolling_managers`, set in their scenes), so a level can hold any number of them. The key and door (`Cle`, `Porte`), post-it and keypad door (`PostIt`, `PorteDigicode`) and colleague (`Collegue`) are optional, with at most one of each per level. To add a level, create a scene in `levels/` with those nodes and add its path to `Game.LEVELS`; `tests/unit/test_levels.gd` checks every listed level. `levels/test_collegue.tscn` is a manual test scene, not in `Game.LEVELS`: the player starts right before the colleague with no manager, so opening it and pressing F6 shows the question after one step to the right. `levels/test_reussite.tscn` is another manual test scene, not in `Game.LEVELS`: the player starts just before the goal with no manager, so pressing F6 and one step to the right shows the success screen. The game has 10 levels (`levels/level_01.tscn` to `level_10.tscn`), longer and harder one after the other, each introducing one mechanic: 1 one watching manager, 2 two watching managers out of sync (half a sweep apart), 3 key and door, 4 a patrolling manager alone, 5 post-it and keypad, 6 colleague, 7 a fast watching manager with a patrol and key/door, 8 two watching managers, a patrol, keypad and colleague, 9 and 10 everything with a time limit (10 adds a second, faster patrol). In every level, the managers' watched areas don't overlap (a watching manager's zone, a patrol's limits plus its vision), and every watching manager never turns away and sweeps left-center-right-center in a loop (`back_duration` 0) above a single desk in the middle of their zone, which holds the key when the level has one. `tests/unit/test_levels.gd` holds the expected content of each level (`EXPECTED`) and checks those two rules, every patrol a desk between its limits, the doors, key and post-it in order on the way, and that the levels get longer. Managers are tuned per level with exports: `facing_duration`, `back_duration`, `sector_duration` and `start_offset` (time already spent in the cycle, so that two watching managers of a level are out of sync; keep `facing_duration` at 5 x `sector_duration` so the scan covers its five steps; a `back_duration` of 0 makes the manager never turn away and sweep left, center, right, center in a loop (`ManagerWatch.SWEEP_ORDER`, `facing_duration` is then ignored), the arrow following without a jump) on `manager/manager.gd`, and `speed` on `manager/patrolling_manager.gd`; the defaults are the constants of `ManagerWatch` and `ManagerPatrol`. A level can have a time limit (`time_limit` export on `level.gd`, 0 = none, used by levels 9 and 10): the timer then counts down (`LevelScore.chrono_seconds`) and turns red in the last 10 seconds (`LevelScore.TIME_WARNING`); when it reaches zero the level fails even if the player is working, and the HR warning reads "Shift over, still not at desk." instead of "Spotted by", stamped "TOO LATE!" (`HrWarning.Spotter.TIME_UP`, `HrWarning.stamp_text`). A level can hold tutorial posters (`level/tutorial_sign.tscn`, `TutorialSign`, with a `text` export): a sheet taped on the wall above the heads, written in Permanent Marker, purely decorative; levels 1, 3, 4, 5, 6 and 9 have one next to their new mechanic.

The description below is the mechanics test scene (`levels/test_mecaniques.tscn`, the former level 1, not in `Game.LEVELS`, tested by `tests/unit/test_level.gd`): a level with the player (`player/`), a manager (`manager/`), two walls, a visual floor and a goal zone. The player starts at the left edge, only moves left and right for now, and the camera follows it. The two concrete-grey walls (`MurGauche`, `MurDroit`) are the ends of the building: `level.gd` sets the player camera's `limit_left` and `limit_right` to their outer edges, and `limit_bottom` at the bottom of the floor (`Sol`), so nothing shows below it (`level/level_bounds.gd`, `LevelBounds`), so the camera never shows past them, the player starts on the left of the screen and the floor sits near the bottom of the screen. The wall visuals go up to y = -900 to cover the whole screen height. Reaching the goal zone near the right wall shows the success screen and freezes the player. The manager stands in the background in the middle of the level and alternates 10 seconds facing the camera and 5 seconds turned away. While facing, they scan the three thirds of the zone around them, 2 seconds each, in the order left, center, right, center, left; being in the watched third shows the game over screen, with the same freeze and restart. An arrow above them sweeps smoothly along an arc to show the scan coming, and reappears 1 second before they turn back to face the camera. Two desks (blue rectangles) sit inside that zone: pressing E on one puts the player in a working state where they stay still and the manager can't spot them; pressing E again or a fresh press of a move key ends it. A second, patrolling manager walks back and forth across the same zone and spots the player in a short area in front of it, unless the player is working. A key sits on the left desk: the first press of E there picks it up without working, and a "Key" indicator shows while the player carries it. A locked door between the managers' zone and the goal blocks the way; pressing E against it with the key opens it (the door disappears and the key is used up). Before the managers' zone, a post-it near the start shows a random 4-digit code while the player stands in front of it after pressing E, and a second door has a keypad: E against it opens a panel where the player types the code (top-row digits by physical position, or the numpad; Backspace erases, Enter confirms, Esc or E closes). The player can't move while the panel is open, but the game keeps running. The right code opens the door; a wrong one costs 100 points, shows "Wrong code" and attracts the patrolling manager, who walks to the keypad even outside their limits, waits 3 seconds and goes back to patrolling. Just inside the zone, a colleague (green) stops the player the first time they walk into them and asks a random office multiple-choice question (`level/quiz_questions.gd`), answered with 1, 2 or 3. The question shows in a speech bubble above the colleague (with "Answer with 1, 2 or 3" in its corner) and the three answers in one thought cloud above and left of the player, lifted above the head; each answer is a row with a drawn keyboard key (`Touche1..3`, the label `Choix<i>` holds only the answer text) and dashed separators (`ui/dashed_line.gd`) between rows (`ui/speech_bubble.gd`, `SpeechBubble`: `place` puts a bubble above a head and keeps it on screen, `avoid` moves the cloud beside the speech bubble when they would overlap; the cloud has no dots of its own, and a `ThoughtTrail` (`ui/thought_trail.gd`) draws evenly spaced dots growing in a straight line from the player's head up to the cloud), over a light veil so the level stays visible. While the question is shown the player can't move and neither manager can spot them. A wrong answer costs 100 points and makes the patrolling manager rush to the colleague at twice their speed. After an answer, a short reaction (`level/quiz_reaction.gd`, `QuizReaction`, 1.2 s) shows the chosen row in green with a hop of the cloud, or in red and struck through (`Rature<i>`) with a shake, and fades the other rows; the player is freed as soon as they answer (no longer protected, and can move and be spotted while the reaction is shown), then the bubbles close; the colleague no longer blocks. A timer in the top right runs from the start of the level and stops at the goal or on game over; reaching the goal shows the time and a score of 1000 minus 10 points per second (never below 0), and a game over shows no score. The installed Godot is the Mono build and `project.godot` has an assembly name, but the project has no C# code; the existing scripts are GDScript.

`ROADMAP.md` lists the milestones, planned features and open questions. Read it when the user gives a new task, and update the statuses there once a feature is done.

## Commands

Tests use GUT 9.4.0 (`addons/gut/`), configured by `.gutconfig.json`. It picks up `test_*.gd` files anywhere under `res://tests/`.

```powershell
# Run all tests headless (exit code 0 = success)
.\run_tests.ps1

# Run one file, or only the tests in it whose name contains a string
$godot = "F:\informatique\Godot_v4.3-stable_mono_win64\Godot_v4.3-stable_mono_win64_console.exe"
& $godot --headless --path . -s "res://addons/gut/gut_cmdln.gd" -gtest=res://tests/unit/test_scene.gd
& $godot --headless --path . -s "res://addons/gut/gut_cmdln.gd" -gtest=res://tests/unit/test_scene.gd -gunit_test_name=instantiates
```

`run_tests.ps1` uses the path above unless `GODOT_BIN` is set. Use the `_console.exe` binary so that output and exit codes reach the shell.

The script runs `--import` first because it registers `class_name`s such as `GutTest`. When calling Godot directly after a fresh clone or after adding an addon or a new `class_name`, run this first:

```powershell
& $godot --headless --path . --import
```

To launch the game for about 2 seconds and list any errors (no output = no errors):

```powershell
& $godot --path . --quit-after 120 *>&1 | Out-String -Stream | Select-String "ERROR"
```

Always check the logs: Godot exits with code 0 even after a script error. `--quit-after` counts frames.

To build the shareable game (Windows and Web), run `.\export.ps1`: it exports both presets of `export_presets.cfg` and writes `builds/BossHide-windows.zip` (a single `BossHide.exe` with the pack embedded) and `builds/BossHide-web.zip` (an HTML5 build for itch.io), each with the font licenses in `licenses/`. `builds/` is ignored by git, and `export.ps1` puts a `.gdignore` in it so Godot doesn't import the built files (the presets also exclude `builds/*`). The export uses the standard (non-.NET) Godot 4.3 in self-contained mode, `F:\informatique\Godot_v4.3-stable_win64\` (a `._sc_` file keeps its settings, the Windows and Web export templates and the `rcedit` path, which sets the exe icon, in its own `editor_data\`), or `GODOT_EXPORT_BIN`. The presets exclude the tests, GUT, `.gutconfig.json` and the manual test scenes (`tests/unit/test_export.gd` checks them). The Web build runs without threads (no COOP/COEP headers needed) and keeps a fixed 1152x648 canvas (`html/canvas_resize_policy` 0), since the interface doesn't scale. The game icon is `icon.svg` (a toilet paper roll with shifty eyes).

Deployment to itch.io is automatic (`.github/workflows/itch.yml`, on a `windows-latest` runner): pushing a tag `vX.Y.Z` (or "Run workflow" in the Actions tab) installs the standard Godot with `ci/install_godot.ps1` (editor, Windows and Web templates checked against the official SHA512 sums, rcedit; cached between runs; also usable locally with `-Destination <folder>`), fails if the tag doesn't match `config/version` in `project.godot`, runs `run_tests.ps1`, then `export.ps1`, attaches both zips to the run, and pushes `builds/windows` to the `windows` channel and `builds/web` to the `html5` channel with butler (version pinned in `BUTLER_VERSION`), with the version as `--userversion`. It needs the `BUTLER_API_KEY` secret and the `ITCH_GAME` variable (`user/game`) in the GitHub repository. To release: bump `config/version`, commit, `git tag vX.Y.Z`, `git push origin master --tags`. `tests/unit/test_deploy.gd` checks the version format and the workflow.

In headless tests, events sent with `Input.parse_input_event` stay buffered until something flushes them, so call `Input.flush_buffered_events()` right after; otherwise a test may pass in the full suite and fail when run alone.

## Conventions

- Tests extend `GutTest` and live in `tests/unit/`. The GUT pre-run hook `tests/pre_run_hook.gd` (`pre_run_script` in `.gutconfig.json`) points `SaveData.path` to `user://test_save.cfg` and deletes it, so tests never touch the player's save; `test_game.gd` deletes it before each test so every game starts at level 1. Wrap instantiated nodes in `autofree()` so they don't leak.
- Comments and assertion messages are in French, written without accents.
- In-game text is in English by default.
- `.gitattributes` normalizes text files to LF.
- `addons/gut/` is third-party code, so don't edit it. The test suite depends on it.
- `run/main_scene` in `project.godot` points to `res://Game.tscn`. `tests/unit/test_scene.gd` and `tests/unit/test_level.gd` each hold that path in their own constant, and `test_level.gd`, `test_level_02.gd` and `test_game.gd` hold the paths of the scenes they load, so update them if a scene moves.

## Rules

- Reply to the user in French.
- Never commit without the user's validation.
- Keep logic separate from the interface so each can be tested on its own:
  - Logic (rules, detection, task state) goes in classes that don't depend on the scene tree and can be tested alone.
  - Nodes only handle display and input.
  - Interface tests check that scenes instantiate and that signals are connected.
- Write at least one test for each new feature.
- Never weaken or delete a test to make it pass. If a test looks wrong, or you are stuck, stop and ask the user.

## Cycle

For each new feature:

1. The user gives a task.
2. Claude enters plan mode and asks all the questions needed to define the scope and anticipate problems or contradictions with earlier rules, before writing any code.
3. Claude writes the tests, then the code, and iterates until the tests pass.
4. Claude launches the game (see Commands) and checks the logs for errors. If needed, it also simulates input or takes a screenshot. How the game feels is left to the user's manual tests.
5. Claude gives the user precise tests to run to check the feature themselves, and opens the project in the Godot editor so they can run them: `Start-Process "F:\informatique\Godot_v4.3-stable_mono_win64\Godot_v4.3-stable_mono_win64.exe" -ArgumentList "--path", ".", "-e"`.
6. Give me a commit name idea

For bugs: only report bugs you have actually observed. Fix one by first writing a test that reproduces it; plan mode is not required.
